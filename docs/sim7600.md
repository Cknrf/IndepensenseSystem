# SIM7600G-H — cellular data + GPS

The Waveshare SIM7600G-H 4G Dongle provides two capabilities for IndepenSense:

- **Cellular data** (LTE via a data-only SIM) — a fallback network when WiFi is
  unavailable, so alerts and status still reach the guardian dashboard when the
  user walks out of a home/university network.
- **GPS / GNSS** — the same module includes a multi-constellation GNSS
  receiver (GPS + GLONASS + BeiDou + Galileo) that streams NMEA sentences on
  a dedicated serial port. Requires a separate external GPS antenna
  (see below).

## Status reference

| Item | Value |
|---|---|
| Hardware | Waveshare SIM7600G-H 4G Dongle (USB) |
| USB vendor:product | `1e0e:9001` (SimTech) |
| Kernel drivers | `option` (5x serial ports) + `qmi_wwan` (network) |
| Modem manager | ModemManager + NetworkManager (Pi OS Trixie stock stack) |
| Data path | QMI over `/dev/cdc-wdm0` → `wwan0` network interface |
| GPS port | `/dev/ttyUSB1` (NMEA stream at 115200 baud) |
| AT command ports | `/dev/ttyUSB2`, `/dev/ttyUSB3` |
| Test SIM | Globe/GOMO (data plan) |
| APN | `internet.globe.com.ph` |
| Route metrics | WiFi 600 (preferred), cellular 700 (fallback) |

## Why the dongle and not the HAT

Waveshare offers both a HAT and a USB dongle version of the SIM7600G-H. The
dongle was chosen because the Pi's 40-pin GPIO header is already fully used
by other sensors (DYP-A22 ultrasonic sensors on UART0 and UART4, MPU6050 IMU
on I2C1). A HAT would physically cover the header and block wire access to
those sensors. The USB form factor also makes cellular a hot-swappable
component during development.

## Why the modem stack was chosen this way

- **QMI over PPP.** The kernel exposes the SIM7600's modem interface as a
  QMI (Qualcomm MSM Interface) device (`/dev/cdc-wdm0`) rather than as a PPP
  serial link. QMI is faster to bring up, more resilient, and is the modern
  Linux default for LTE modems.
- **ModemManager + NetworkManager over direct `qmicli` + `udhcpc`.**
  ModemManager provides a nice abstraction (`mmcli`, `nmcli`) and
  auto-reconnects on failure. Direct QMI would work but requires more shell
  scripting and lacks the reboot-persistence NetworkManager gives for free.

## Prerequisites

The Pi OS Trixie kernel already includes the `option` and `qmi_wwan` drivers.
Only ModemManager needs installing — it is not part of the default Pi OS
image:

```bash
sudo apt update
sudo apt install -y modemmanager
mmcli --version
```

A **data-only SIM** (Globe, Smart, DITO, or GOMO) with an active plan.

An **external GPS antenna** — the Waveshare package ships **only the LTE
antenna**. A separate active GNSS antenna with SMA connector is required for
GPS to obtain a fix.

## Verify hardware detection

Plug the dongle into any USB port on the Pi (USB-A recommended for reliable
power delivery). Confirm the kernel sees it:

```bash
lsusb | grep -i 'sim\|1e0e'
# Expected: "1e0e:9001 Qualcomm / Option SimTech, Incorporated"

ls /dev/ttyUSB*
# Expected: /dev/ttyUSB0 through /dev/ttyUSB4 (five serial ports)

ip link show wwan0
# Expected: an interface named wwan0 (may be DOWN initially)
```

## The "No modems found" gotcha

After a fresh `apt install modemmanager`, `mmcli -L` will often report
`No modems were found` even though the kernel shows the modem attached.
This is because ModemManager only probes for modems at USB hotplug events,
not at daemon startup — so a modem plugged in **before** ModemManager was
installed is invisible.

Fix: restart ModemManager and physically re-plug the dongle.

```bash
sudo systemctl restart ModemManager
# unplug the dongle from USB, wait 3 seconds, plug back in
sleep 10
mmcli -L
```

Expected output:

```
/org/freedesktop/ModemManager1/Modem/N [QUALCOMM INCORPORATED] SIMCOM_SIM7600G-H
```

(The modem index `N` may be 0 or higher depending on prior connections. Use
`mmcli -m any` if unsure — it always resolves to the first available modem.)

## Verify the SIM registered

Insert the SIM (with the dongle unplugged), plug the dongle back in, then:

```bash
mmcli -m any
```

Look for these lines in the output:

- `state: registered`
- `access tech: lte`
- `signal quality: <NN%>` — 30% and above is comfortable indoors
- `operator name:` — should show your carrier (e.g. "Globe Telecom-PH")
- `packet service state: attached`

A `sim-pin2` lock in the Status block is normal for many SIMs; it protects
premium services (fixed-dialing numbers) and does not block data.

## Bring up the data connection

Create and activate a mobile broadband connection profile in NetworkManager.
The APN below is for Globe/GOMO; use your carrier's APN if different.

```bash
sudo nmcli connection add type gsm ifname '*' con-name gomo apn internet.globe.com.ph
sudo nmcli connection up gomo
```

Confirm an IP was assigned and packets flow:

```bash
ip addr show wwan0
# Expected: "inet 100.<x>.<y>.<z>/<prefix>" — Globe's carrier-grade NAT range

ping -c 4 -I wwan0 8.8.8.8
# Expected: 4/4 packets received, latency 25-100 ms after the first packet
```

The first packet is often ~200-300 ms while the modem completes the bearer
setup; subsequent packets settle to the low tens of milliseconds.

## Make it persist across reboots

```bash
sudo nmcli connection modify gomo connection.autoconnect yes
sudo nmcli connection modify gomo connection.autoconnect-retries 0
```

`autoconnect-retries=0` means "retry forever" — after coverage loss the
wearable will keep attempting reconnect indefinitely without manual
intervention.

## Verify WiFi is preferred over cellular

Both networks will be active simultaneously. Confirm the Pi routes through
WiFi when it is available (cheaper, faster) and falls back to cellular only
when WiFi drops.

```bash
ip route show default
```

Expected:

```
default via <wifi-gw> dev wlan0 proto dhcp src <ip> metric 600
default via <cell-gw> dev wwan0 proto static metric 700
```

Lower metric wins. NetworkManager assigns metric 600 to WiFi and 700 to
cellular automatically because it treats mobile broadband as "metered" by
default — no manual configuration required.

## Refresh cycle after a SIM change or carrier change

If the SIM is swapped or the APN changes:

```bash
sudo nmcli connection down gomo
sudo nmcli connection modify gomo gsm.apn <new-apn>
sudo nmcli connection up gomo
```

## Troubleshooting

- **`mmcli -L` reports "No modems found":** run the re-plug sequence above.
  If still empty after that, `sudo systemctl status ModemManager` to check
  the daemon is running, and `sudo journalctl -u ModemManager -f` while
  re-plugging to see live probe logs.
- **`nmcli connection up gomo` fails with "Activation failed":** APN
  mismatch. Try `internet` or `gomo` as the APN value.
- **Ping through `wwan0` times out despite registration:** check
  `mmcli -m any` for `packet service state: attached`. If it says `detached`
  the SIM is registered for voice but not data — usually a plan/carrier
  issue, not a Pi issue.
